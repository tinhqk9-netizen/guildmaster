# 05. Batch 1 UI & Backend Mismatch Matrix (Đã Cập Nhật Thực Tế)

Báo cáo phân tích so sánh chi tiết giữa kịch bản hiển thị của Giao diện người dùng (UI Controller) và logic xử lý nghiệp vụ thực tế của Backend Services & Save Model.

## Bảng Ma Trận So Sánh Các UI Action & Backend Mismatch

| UI Screen & Action | Backend Service & Save Path | Cơ Chế Cập Nhật Dữ Liệu & API | Chênh Lệch Thực Tế (Mismatch & Limitations) | Dẫn Chứng Code |
| :--- | :--- | :--- | :--- | :--- |
| **Recruit Guest**<br>(Tuyển Hero tại TavernScreen) | **ITavernService** & `SaveData.TavernGuests` -> `SaveData.Characters` | - Gọi `RecruitGuest(index, out _)` trên `TavernService`. Trả về `CharacterRuntime`. | - Chỉ số Hero và class được generate ngẫu nhiên lưu trong list `TavernGuests` của Save Data.<br>- Tiền tệ kiểm tra qua `_saveService.CurrentData.Money` trực tiếp. Không có mismatch kiểu dữ liệu (đều dùng `long` Money). | - UI: `TavernScreen.cs:182-201`<br>- Backend: `TavernService.cs:68-81` |
| **Upgrade Tavern Buildings**<br>(Nâng cấp Quarters/Tavern) | **ITavernService** & `SaveData.LevelQuarters`, `LevelTavernCapacity`, `LevelTavernTime` | - Gọi `UpgradeQuarters()`, `UpgradeTavernCapacity()`, `UpgradeTavernTime()`. Trừ tiền `Money` trực tiếp trong SaveData. | - UI hiển thị dưới dạng chuỗi: `Cost: {price}g`. Giá nâng cấp được tính toán qua `IFormulaService` (vd: `GetUpgradeQuartersPrice()` trả về `long`). Cả hai đầu thống nhất kiểu dữ liệu `long`. | - UI: `TavernScreen.cs:130-160`<br>- Backend: `TavernService.cs:217-261` |
| **View Character Details**<br>(Xem chi tiết Adventurer) | **ICharacterService** & `SaveData.Characters` | - Gọi `GetAllCharacters()` lấy list nhân vật.<br>- Gọi `GetTotalStat(c, statType)` để lấy tổng chỉ số. | - Chỉ số nhân vật gốc lưu trong `CharacterSaveData` nhưng chỉ số hiển thị ở UI là chỉ số tổng (sau khi tính toán bối cảnh class growth, gear, status effects qua `IFormulaService`). | - UI: `CharacterScreen.cs:118-127`<br>- Backend: `CharacterService.cs:10-15` |
| **Equip Item to Character**<br>(Trang bị vật phẩm) | **IEquipmentService** & `CharacterSaveData.WeaponInstanceId`/`ArmorInstanceId`/`AccessoryInstanceId` | - Gọi `_equipmentService.Equip(target, itemId, slot)`. Trả về `bool` thành công. | - **UI Logic Mismatch**: Do UI không truyền slot cụ thể được người chơi click, UI `CharacterScreen.cs:224-226` tự động gọi lần lượt `Equip` cho 3 slot (Weapon, Armor, Accessory) và dừng lại ở slot đầu tiên trả về `true`. Cách này tự động hóa nhưng làm giảm kiểm soát của người chơi trên UI. | - UI: `CharacterScreen.cs:218-230`<br>- Backend: `EquipmentService.cs:14` |
| **Manage Battle Party**<br>(Tổ chức đội hình) | **UI Local State ONLY** (Không lưu trữ trong Save!) | - Trạng thái party lưu trực tiếp trong biến private `_partyIds` (HashSet) của UI `CharacterScreen.cs:36`. | - **Mismatch kiến trúc nghiêm trọng**: Party không hề có save path hay trường dữ liệu nào trong schema `SaveData.cs`! Toàn bộ trạng thái party sẽ bị reset sạch sẽ khi người chơi thoát game or tải lại scene, gây phiền toái vì phải chọn đội hình lại từ đầu. | - UI: `CharacterScreen.cs:36`, `61-74`<br>- Backend: `SaveData.cs` |
| **Claim Quest Reward**<br>(Nhận thưởng nhiệm vụ) | **IQuestService** & `SaveData.Quests`, `Gems`, `WarProgress`, `EconomyProgress`, `GrowthProgress` (Doctrine progress) | - Gọi `ClaimReward(questInstanceId, selectedDoctrine)`. | - **Mismatch cơ chế thưởng**: UI hiển thị Doctrine tuyển chọn ở mọi Quest, tuy nhiên Backend `QuestService.cs:183-196` quy định: nếu Quest có Rarity >= 4 (Quest đặc biệt), giải thưởng mặc định luôn là **Gems** và phớt lờ Doctrine tuyển chọn. Chỉ Quest Rarity < 4 mới tăng Doctrine Progress. | - UI: `QuestScreen.cs:29`, `146-162`<br>- Backend: `QuestService.cs:176-202` |
